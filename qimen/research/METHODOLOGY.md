## 1. Signal Construction

### 1.1 Qimen Dunjia Engine Specification

The QSI is generated by the QMDJ computational engine (`qimen/engine.py`), which follows a deterministic pipeline:

```
Input: datetime (UTC+8)
  ↓
Step 1: Four Pillars Calculation (四柱)
  - Year Stem-Branch, Month Stem-Branch, Day Stem-Branch, Hour Stem-Branch
  - Base date: 2000-01-07 = 甲子日 (validated against perpetual calendar)
  ↓
Step 2: Solar Term & Yuan Determination (節氣元局)
  - Identify current jieqi (e.g., 立秋, Aug 7)
  - Calculate day offset from jieqi
  - Determine yuan: offset 0-4 = 上元, 5-9 = 中元, 10-14 = 下元
  - Look up ju number from JU_TABLE (e.g., 立秋中元 = 陰遁五局)
  ↓
Step 3: Xun Head & Offset (旬首與值符值使)
  - Find current xun (旬) from hour stem-branch
  - Determine zhifu (值符/star) and zhishi (值使/gate)
  - Calculate offset (how many steps stars/gates fly from home palaces)
  ↓
Step 4: Earth Plate (地盤)
  - Fixed for ~5 days within each xun cycle
  - 9 palaces with assigned stem-branch combinations
  ↓
Step 5: Sky Plate (天盤) — Star + Stem flying
  - Stars fly according to offset, direction (Yin=Yin path, Yang=Yang path)
  - Special rule: 天禽 (Star 5) always resides in 坤 (Palace 2) during calculations
  - Each star carries its associated heavenly stem
  ↓
Step 6: Human Plate (人盤) — Gate flying
  - Eight gates fly according to offset and direction
  - Gate 5 (中門/Dead Gate) stays at center, others rotate
  ↓
Step 7: Spirit Plate (神盤) — Deity flying
  - Eight deities (值符, 螣蛇, 太陰, 六合, 白虎, 玄武, 九地, 九天)
  - Fly according to offset
  ↓
Step 8: Void Detection (空亡)
  - Identify which branches are void in current xun
  - 甲申旬 → 午未空; 甲戌旬 → 申酉空; etc.
  - If void branches affect key palaces (e.g., metal palaces 6/7 for EUR), signal is penalized
  ↓
Step 9: Pattern Detection (格局)
  - Detect auspicious patterns (吉格): 青龍返首, 飛鳥跌穴, etc.
  - Detect inauspicious patterns (凶格): 青龍逃走, 白虎猖狂, etc.
  ↓
Step 10: Scoring & Output
  - Apply scoring formula → QSI(t)
```

### 1.2 Scoring Formula

For a specific trading question (e.g., "Will EUR/USD rise in the next 1-2 hours?"), the engine identifies the relevant yong shen (用神) and computes:

```
QSI(t) = Σ component scores

Component 1: Gate-Palace Relationship (門宮生剋)
  - 生門 at Metal Palace (乾6/兌7) → 得生 (strong) → +2
  - 生門 at Water Palace (坎1) → 洩氣 (weak)   → -1
  - 生門 at Fire Palace (離9)  → 壓制 (down)   → -2
  - 生門 at Earth Palace (坤2/艮8) → 比和 (neutral) → 0

Component 2: Metal Palace Void (金宮空亡)
  - If 申 or 酉 are void (甲戌旬) → Metal palaces 6/7 hollowed → -2
  - Otherwise → 0

Component 3: Fuyin Pattern (伏吟局)
  - If offset = 0 (all at home palaces) → stagnation → -1
  - Otherwise → 0

Component 4: Fire Restraining Metal (火剋金)
  - For each fire-related star/gate at metal palace → -1 each

Component 5: Water Draining Metal (水洩金)
  - For each water-related star/gate at metal palace → -1 each

Component 6: Pattern Bonus (格局加分)
  - Auspicious patterns detected → +1 to +3
  - Inauspicious patterns detected → -1 to -3

Total Range: approximately [-10, +8]
```

### 1.3 Time-Series Alignment

```
For each shichen boundary (every 2 hours):
  t = [00:00, 02:00, 04:00, 06:00, 08:00, 10:00,
       12:00, 14:00, 16:00, 18:00, 20:00, 22:00]

  Generate QSI(t) at the START of each shichen
  Align with the next 1-2 hour OHLC candle(s)

  Example:
  QSI(11:00) = +3  →  Signal for 11:00-13:00 window
  Compare against EURUSD return from 11:00 to 13:00
```

## 3. Experimental Design

### 3.1 Experiment 1: QSI Univariate Predictive Power

**Objective**: Test whether QSI alone can predict directional price movement.

**Hypothesis**:
- H0: QSI has no predictive power (AUC = 0.5)
- H1: QSI has significant predictive power (AUC > 0.5)

**Method**:
```
Model: Logistic Regression
Features: [QSI]
Target: target_binary_2h (up/down in next 2 hours)

Metrics:
  - AUC-ROC
  - Accuracy
  - Precision, Recall, F1
  - Statistical significance (Wald test on QSI coefficient)

Additional analysis:
  - QSI distribution plot
  - QSI vs. forward return scatter plot
  - QSI decile analysis (sort by QSI, group into 10 deciles, compare avg returns)
```

**Decision rule**: If p-value < 0.05 on QSI coefficient AND AUC > 0.52, proceed to Experiment 2.

### 3.2 Experiment 2: Incremental Information Value (CRITICAL)

**Objective**: Does QSI add predictive value BEYOND conventional technical indicators?

**Models**:
```
Model A (Baseline):  Technical indicators only
  Features: [RSI, MACD_signal, ADX, BB_position, EMA_slope, ATR, Stoch_K, Volume_ratio]

Model B (Enhanced): Technical indicators + QSI
  Features: [RSI, MACD_signal, ADX, BB_position, EMA_slope, ATR, Stoch_K, Volume_ratio, QSI]
```

**ML Algorithms tested** (each applied to both Model A and Model B):

| Algorithm | Hyperparameter Tuning | Cross-Validation |
|-----------|----------------------|-----------------|
| Logistic Regression | L1/L2 penalty, C | 5-fold time-series CV |
| Random Forest | n_estimators, max_depth, min_samples_leaf | 5-fold time-series CV |
| XGBoost | learning_rate, max_depth, n_estimators, reg_alpha, reg_lambda | 5-fold time-series CV |
| LightGBM | num_leaves, learning_rate, n_estimators | 5-fold time-series CV |
| LSTM | hidden_size, num_layers, dropout, learning_rate | Walk-forward CV |

**Comparison Metrics**:
```
For each algorithm:
  AUC_A  vs  AUC_B  →  ΔAUC = AUC_B - AUC_A
  Sharpe_A vs Sharpe_B → ΔSharpe

Statistical test for ΔAUC:
  DeLong test for paired AUC comparison
  H0: ΔAUC = 0
  H1: ΔAUC > 0
```

**Visualization**: Paired bar charts showing Model A vs Model B metrics across all algorithms.

### 3.3 Experiment 3: Feature Importance & Ablation

**Objective**: How important is QSI relative to other features?

**Method A — SHAP Values**:
```

Calculate SHAP values for all features

```

```
...

Marginal contribution of QSI = Performance_Full - Performance_noQSI
Compare against marginal contribution of each other feature
```

### 3.4 Experiment 4: QSI Component Analysis

**Objective**: Which sub-components of QSI contribute most?

```
QSI = Star + Gate + Deity + StemBranch + Pattern + Void + Fuyin

For each component:
  - Calculate correlation with forward returns
  - Run univariate logistic regression
  - Compare AUC
  - Analyze interaction effects (pairwise correlation between components)

Output: Ranked list of QSI sub-component importance
```

### 3.5 Experiment 5: Market Regime Analysis (RQ3)

**Objective**: Does QSI effectiveness vary across market conditions?

```
Split data into regimes:
  1. Trending vs. Range-bound (based on ADX threshold)
  2. High volatility vs. Low volatility (based on ATR percentile)
  3. Risk-on vs. Risk-off (based on VIX threshold)

For each regime:
  Run Experiment 2 (Model A vs Model B)
  Compare ΔAUC and ΔSharpe across regimes

Expected pattern (hypothesis):
  - QSI may be more effective in range-bound markets
    (where traditional trend indicators struggle)
  - QSI may be less effective in high-volatility events
    (where macro factors dominate)
```

## 4. Risk Metrics Framework

### 4.1 Portfolio Construction for Risk Testing

```
Strategy 1: QSI-only
  - LONG when QSI ≥ +2, SHORT when QSI ≤ -2, FLAT otherwise

Strategy 2: Technical-only
  - Based on Model A predictions (threshold = 0.5 probability)

Strategy 3: Combined (QSI + Technical)
  - Based on Model B predictions

Strategy 4: Benchmark (Buy & Hold)
  - Always long EUR/USD

Strategy 5: Random
  - Random entry/exit with same position frequency as Strategy 1
```

### 4.2 Risk Metrics Calculation

```python
# For each strategy, calculate:

def calculate_risk_metrics(returns):
    metrics = {}

    # Return metrics
    metrics['total_return'] = (1 + returns).prod() - 1
    metrics['annualized_return'] = (1 + returns.mean())**252*12 - 1  # hourly → annualized
    metrics['volatility'] = returns.std() * np.sqrt(252*12)

    # Risk-adjusted returns
    metrics['sharpe'] = metrics['annualized_return'] / metrics['volatility']
    negative_returns = returns[returns < 0]
    metrics['sortino'] = metrics['annualized_return'] / (negative_returns.std() * np.sqrt(252*12))

    # Drawdown
    cumulative = (1 + returns).cumprod()
    running_max = cumulative.cummax()
    drawdown = (cumulative - running_max) / running_max
    metrics['max_drawdown'] = drawdown.min()
    metrics['max_drawdown_duration'] = (drawdown == 0).idxmax()  # longest flat period

    # Tail risk
    metrics['var_95'] = np.percentile(returns, 5)
    metrics['var_99'] = np.percentile(returns, 1)
    metrics['cvar_95'] = returns[returns <= metrics['var_95']].mean()
    metrics['cvar_99'] = returns[returns <= metrics['var_99']].mean()

    # Strategy metrics
    metrics['win_rate'] = (returns > 0).mean()
    metrics['profit_factor'] = returns[returns > 0].sum() / abs(returns[returns < 0].sum())
    metrics['avg_win'] = returns[returns > 0].mean()
    metrics['avg_loss'] = returns[returns < 0].mean()
    metrics['expectancy'] = metrics['win_rate'] * metrics['avg_win'] + \
                         (1 - metrics['win_rate']) * metrics['avg_loss']

    return metrics
```

## 5. Statistical Testing Protocol

### 5.1 Multiple Testing Correction

Given multiple experiments and models, we apply:
- **Bonferroni correction** for family-wise error rate control
- **Benjamini-Hochberg procedure** for false discovery rate control

### 5.2 Significance Thresholds

| Test | Alpha | Corrected Alpha (Bonferroni, k=10) |
|------|-------|----------------------------------|
| Primary (Exp 2: ΔAUC) | 0.05 | 0.005 |
| Secondary (Exp 1, 3, 4) | 0.05 | 0.01 |
| Exploratory (Exp 5) | 0.10 | 0.02 |

### 5.3 Power Analysis

```
Minimum detectable effect size for ΔAUC:
  - n ≈ 40,000 observations (11 years × 12 signals/day × ~300 trading days)
  - With α = 0.005, power = 0.80
  - Minimum detectable ΔAUC ≈ 0.008 (0.8 percentage points)

This means: if QSI adds even a tiny 0.8% improvement in AUC,
we have sufficient statistical power to detect it.
```

## 7. Ethical Considerations

### 7.1 Research Integrity

- This research does NOT claim to validate or invalidate QMDJ as a metaphysical system
- It tests whether QSI, as a quantified signal, has incremental predictive power for FX returns
- Null results (no predictive power) are equally valuable and will be reported honestly
- The cultural framework is treated as a "black box signal generator" — the internal logic is documented but not judged

### 7.2 Cultural Sensitivity

- QMDJ is treated with academic respect as a culturally significant decision-making system
- No mocking or dismissal of traditional Chinese culture
- The framing is: "Can structured cultural data serve as alternative data in finance?"
- This aligns with the broader academic investigation of cultural influences on financial behavior

### 7.3 Financial Disclaimers

- This is academic research, NOT investment advice
- No real money will be used; all testing is on historical data
- Results should not be interpreted as endorsement of using QMDJ for actual trading
